# SupplierFlow RAG 完整说明

从头到尾解释：我做了什么、每一步在干嘛、背后的原理是什么。

---

## 一、先讲原理：RAG 到底是什么

### 开卷考试的比喻

AI 模型（DeepSeek）是一个聪明的学生，但它**没有背过**你的产品目录和公司政策。
所以在它回答客户之前，我们要先帮它把相关资料翻出来，摊在桌上。

三个角色：

| 角色 | 对应到系统 | 工作 |
| --- | --- | --- |
| 图书馆 | Supabase 的 `knowledge_chunks` 表 | 存放切碎的文件 |
| 图书管理员 | `knowledge-retrieval.mjs` | 找出跟问题相关的资料 |
| 学生 | DeepSeek | 只读那些资料，然后写答案 |

**最关键的一句话：如果图书管理员拿错资料，学生再聪明也答不对。**
所以测试要分两层——先测「有没有找对资料」，再测「有没有答对」。

### 完整流程

```
客户提问
   ↓
① 把问题转成 1536 个数字（向量）           ← OpenAI text-embedding-3-small
   ↓
② 在资料库里找出「意思最接近」的几块        ← pgvector 余弦相似度
   ↓
③ 检查相似度够不够高                       ← 相似度门槛 0.35
   ↓  （不够高 → 回传 0 块 → 告诉模型「没有资料」）
④ 把找到的资料贴进指令里                    ← SUPPORT KNOWLEDGE:
   ↓
⑤ DeepSeek 只根据这些资料回答
```

## 二、切块与向量：背后到底在算什么

### 为什么要切块（chunking）

一份文件几千字，整份塞给 AI 有两个问题：浪费额度，而且重点被稀释。
所以切成每块 180 个词。客户问「送货要多久」，只需要送货那一小段，不需要整份保固政策。

你的资料库切完是 **12 块**（其中官方产品知识档 7 块，四份政策档各 1 块，另外还有一份 `How to order?`）。

### 向量是什么

`text-embedding-3-small` 把每一块文字转成 **1536 个数字**。
可以想成是一个「意思的坐标」：

- 「送货需要 1-2 个工作天」和「运送时程」→ 坐标很接近
- 「保固三年」→ 坐标离很远

搜寻的时候，把**客户的问题**也转成 1536 个数字，然后算哪一块的坐标最接近。
这个「接近程度」叫**余弦相似度**，介于 0 到 1，越接近 1 表示意思越像。

实测你的资料：

- 有答案的问题：相似度 0.411 ~ 0.774（中位数 0.602）
- 没答案的问题：相似度 0.387 ~ 0.568（中位数 0.469）

**这两个范围重叠得很严重**，这点后面很重要。

## 三、两种找资料的方法

### 关键字（keyword）

数一数问题和每一块有多少相同的字词，最多的赢。

- 强项：精确型号。`A9F73140` 要嘛有、要嘛没有，不会搞错。
- 弱项：换句话说。客户问「缺货」，文件写「无法提供」→ 完全没有共同字词 → 找不到。

### 向量（vector）

比对意思接近程度。

- 强项：换句话说。「缺货」和「无法提供」坐标接近。
- 弱项：极相似的料号。`LC1D09BD` 和 `LC1D09BNE` 只差两个字元，对数学来说意思几乎相同。

### 混合（hybrid）

两个都跑，再用 **RRF（倒数排名融合）** 合并：
每一块依照它在各自排名中的名次给分（第 1 名得分最高），两边都找到的那块分数最高，排到最前面。

结果：**两边各自漏掉的，另一边补上了。**

## 四、我做了什么（按顺序）

### 第 1 步：读程式码，发现根本没有在用向量

我先检查你的专案，发现一件重要的事：

- `schema.sql` 里**有** pgvector、`vector(1536)` 栏位、`match_knowledge_chunks` 函式
- 但这个函式在**整个专案里从来没有被呼叫过**
- 而且当时没有 `OPENAI_API_KEY`，所以每一块的 `embedding` 都是 `NULL`

结论：**当时跑的是纯关键字检索，向量那套是装好了但没接上。**

### 第 2 步：出 50 道题

| 类型 | 数量 | 用途 |
| --- | --- | --- |
| 直接查询 | 30 | 一般问题，答案明确 |
| 刁难题 | 10 | 相似料号、需要同时查多份文件 |
| **陷阱题** | 10 | **答案根本不在资料库里，正确行为是说「我没有这个资料」** |

陷阱题最重要。举例 N10：客户问「SST 税率多少？」——你的 SOP 里**有**「SST」这三个字，但**没有**百分比。
检索会很有信心地把那块拿出来，模型看到上下文真的有「SST」，就很可能自己编一个「6%」出来。
看起来很专业，其实完全是捏造的，而客户可能真的照这个报价。

### 第 3 步：先验证题库本身

这一步很多人会跳过，但如果我写的「标准答案」本身就错了，后面所有分数都没有意义。
`verify-groundtruth.mjs` 会检查每个标准答案是不是真的出现在我标注的那份文件里。

**这个检查抓到我自己写错的东西**（后面第七节详述）。

### 第 4 步：离线测检索

不需要伺服器、不需要金钥，直接读 `data/` 的档案，用**production 完全一样的**切块方式和排序函式。

第一次结果：**Recall@1 只有 62.5%**。

而且 15 次失败里，赢过正确文件的**全部都是同一个档案**：`rag-benchmark-sources.md`。

原因：那个档案只是一份网址清单，但网址里包含料号，例如
`...idpn-n-vigi-1p-n-25a-c-curve-6000a-a-type-30ma-a9d32625.html`。
关键字评分只是数字词有没有出现，所以这个档案在几乎所有产品问题上分数都很高——但它里面**没有真正的答案**。

把它从索引移除后：**62.5% → 100%**。

### 第 5 步：补上缺的东西

1. **资料库迁移** — 帮 `match_knowledge_chunks` 加上「相似度门槛」。
   原本它永远回传 5 块，就算问题根本没答案，也会回传「最不糟的 5 块」——这正是捏造答案的温床。
   加了门槛之后，如果没有够接近的，就回传 **0 块**。

2. **汇入脚本** — `data/` 里的档案只是硬碟上的档案，**不等于资料库**。
   必须汇入到 Supabase，聊天机器人才读得到。这个脚本一次做完切块、转向量、写入。

3. **接上向量检索** — 用 `RETRIEVAL_MODE` 切换 keyword / vector / hybrid，**预设仍是 keyword，不改变现有行为**。

4. **强化指令** — 明确告诉模型：某个产品的数字不适用于另一个产品；没有的资料就说没有。

### 第 6 步：A/B 对比三种方式

| 模式 | 可回答 | 失败题 |
| --- | --- | --- |
| keyword | 39/40 | A09 |
| vector | 38/40 | A09、**D11** |
| hybrid | **40/40** | 无 |

**D11 印证了预测**：问 `LC1D09BD` 的线圈电压，向量找成了 `LC1D09BNE` 的卡片——两个型号只差两个字元。这就是相似料号的弱点，在你的真实目录上被验证了。

### 第 7 步：实际跑 50 题（端到端）

**结果：47/50，捏造率 0/10。**

十道陷阱题**全部通过**——没有编价格、没有编 SST 税率、没有编信用额度。这是最重要的一项。

## 五、三个失败，其中一个不是真的失败

### A05 — 是我的评分程式写错，不是系统的错

模型的答案**完全正确**，它写的是 `Tripping curve: B`。
但我的比对规则要求出现 `b curve` 这个顺序，所以判定失败。

**答案对，评分错。** 已修正成两种顺序都接受。

### D26 — 真的缺，而且是我造成的

客户问「rated fault current」——这是 Eaton 对 30 mA 剩余电流灵敏度的官方说法。
但这个词只出现在 `rag-benchmark-sources.md`，也就是**我建议你不要索引的那个档案**。

所以我的第 4 步修正有个我没预料到的副作用。
已经在 PF7 产品卡里补上这个同义词，而不是把整份网址清单加回索引。

值得注意模型的反应：
> 「我这边没有单独列出 rated fault current 这个数值，如果你需要，我可以请业务团队确认。」

它**选择不猜**。答案不完整，但很安全。

### A09 — 真的失败，跟 A/B 预测的一模一样

> 「送货时程和费用取决于地点和需求日期——我这边没有固定的送货时程可以确认。」

送货政策那一块**根本没送到模型手上**。你目前跑的是 keyword 模式（`.env` 里没有设 `RETRIEVAL_MODE`），
而 A/B 显示这正是 keyword 唯一失败的那题，hybrid 是 40/40。

## 六、最后一个修正：有闸门的 hybrid

原本的 hybrid 有个结构性问题：它一定会混入关键字结果，而关键字**永远不会是空的**，
所以 hybrid 的「拒答率」是 0/10——等于放弃了说「我不知道」的能力。

改成**用向量当闸门**：

```
向量搜寻 → 有没有任何一块超过相似度门槛？
              ├─ 没有 → 回传 0 块（拒答），不退回关键字
              └─ 有   → 关键字也跑一次，两边用 RRF 合并
```

这样就同时拿到 hybrid 的高命中率**和**向量的拒答能力。已加上测试锁住这个行为。

## 七、我自己犯的错（这部分很重要）

这套测试工具抓到的**头三个 bug 都在我自己写的程式里**：

1. **比对太宽松** — `type A` 会错误地匹配到 `type AC` 里面。相似料号的题目会全部误判为通过。
2. **抓捏造的规则写错** — 正则表达式多跳脱了一层，**永远不会触发**。
   也就是说 10 道陷阱题会显示**假的满分**。
3. **词序太死** — 就是上面的 A05。

第 2 点最危险：一个坏掉的评分器会安静地回报「全部通过」。
所以我另外写了 `grader.test.mjs`，**测试这个测试工具本身**。
